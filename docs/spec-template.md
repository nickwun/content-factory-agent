# 内容工厂需求 Spec 模板

适用范围：
- `wechat_article`
- `markdownBody`
- `finalization`
- `post-trimmer`
- 批量仿写
- 发布链路
- preset 机制

目标：
- 让后续需求在真正开发前先把“主真相、兼容层、验收口径”说清楚
- 降低返工、误改主链路和无效 prompt 微调

---

## 1. 目标

这轮要解决什么问题？

建议写法：
- 只写本轮目标，不把后续想法混进来
- 明确这轮是改：
  - 生成
  - 编辑
  - 发布
  - 批量
  - 历史兼容
  - preset

示例：
- 让 `wechat_article` 发布链路改成 `markdownBody` 优先输入
- 让批量仿写继续复用单篇 `/api/generate`
- 让公众号成稿模式从三步压成两步

---

## 2. 当前问题

当前链路具体卡在哪里？

建议至少写清：
- 现在的主真相是什么
- 旧兼容层还在哪里
- 当前真正的问题是“方向错了”还是“已经可用但偏弱”

示例：
- 当前 `markdownBody` 已是生成真相和编辑真相，但发布仍主要依赖兼容出来的 `blocks`
- second-stage 已可用，但解释型重复仍偏多
- 批量仿写已可跑，但成功项入口还不够顺

---

## 3. 设计原则

这轮开发必须守住什么？

建议固定回答：
- 主真相是什么
- 兼容层是什么
- 哪些不要动
- 哪些不要顺手扩大

内容工厂常见原则示例：
- `markdownBody` 是公众号正文主真相
- `blocks` 是兼容层 / 过渡层，不再作为新能力的主真相
- 批量仿写 = 多次复用现有单篇链路，不新起系统
- second-stage 是“收束”，不是“重写”
- post-trimmer 只做减法，不做改写

---

## 4. 明确行为

把这轮最终行为写死，不要留模糊空间。

建议用下面格式：

### 输入
- 这轮主要输入是什么？

### 输出
- 这轮输出什么？

### 优先级
- 主路径优先级是什么？
- 兜底回退是什么？

### 失败处理
- 失败时回退什么？
- 不允许出现什么副作用？

示例：
- 如果存在 `markdownBody`，发布时优先从 `markdownBody` 导出 HTML
- 如果没有 `markdownBody`，再回退到 `blocks`
- 如果 second-stage 失败，则回退初稿
- 批量成功一篇落一篇，但不自动切 active record

---

## 5. 实现边界

把这轮不做的东西列清楚。

建议直接写：
- 不改什么
- 不删除什么
- 不扩到什么
- 不顺手做什么

内容工厂常见边界示例：
- 不改创作页主 UI
- 不改公众号 Markdown 编辑器布局
- 不扩其他平台
- 不一次性删除 `blocks`
- 不做全量历史迁移
- 不把裁剪器升级成新的大模型重写链路

---

## 6. 验收标准

这轮完成后，怎么判断“真的成立”？

建议分成：

### 链路验收
- 主路径是否打通？

### 兼容验收
- 旧记录 / 兜底路径是否正常？

### 页面验收
- 页面上用户是否能真实用起来？

### 回归验收
- 哪些核心链路不能被带坏？

内容工厂推荐最小验收问题：
- 生成真相是否正确？
- 编辑真相是否正确？
- 发布主输入是否正确？
- 自动保存 / 刷新恢复是否正常？
- 旧记录兼容是否正常？
- `npm run lint` 是否通过？
- `npm run build` 是否通过？

---

## 使用提醒

后续每个新需求，建议先回答完这 6 段再开工：
1. 目标
2. 当前问题
3. 设计原则
4. 明确行为
5. 实现边界
6. 验收标准

如果这 6 段里有一段写不清，通常说明这轮需求还没收住。
