# 内容工厂工作规则

这份规则只服务当前项目，不是通用 AI 开发手册。

重点目标：
- 少返工
- 少误改主链路
- 少在高成本动作上“先动手后校正”
- 把 `wechat_article` 的主真相、兼容层和验收口径先说清楚

---

## 1. 高成本动作前，先复述理解

对于下面这些改动，AI 在真正执行前，必须先复述它理解的任务：

- 生成链路改动
- 发布链路改动
- 批量任务执行逻辑改动
- 历史数据兼容改动
- `markdownBody` 主真相相关改动
- prompt / skill 主链路改动

这条规则不是建议，而是执行前置动作。

---

## 2. 复述必须包含的 5 件事

在执行高成本动作前，复述至少要包含：

1. 目标是什么
2. 输入是什么
3. 输出是什么
4. 不允许改什么
5. 这轮验收看什么

推荐写法：

### 目标
- 这轮要解决什么，不解决什么

### 输入
- 当前主输入字段 / 模块 / 页面入口是什么

### 输出
- 改完后主输出应该变成什么

### 不允许改什么
- 明确列边界，例如：
  - 不改 UI
  - 不删 `blocks`
  - 不扩到其他平台

### 验收看什么
- 页面是否成立
- 历史是否兼容
- 发布是否正常
- lint / build 是否通过

---

## 3. 内容工厂里的主真相规则

当前项目内，必须优先按下面这些真相判断：

### 公众号正文
- 主真相：`markdownBody`
- 兼容层：`blocks`

### 公众号第二段
- second-stage 是“收束器”
- 不是“重写器”

### 公众号后处理
- `post-trimmer` 只做减法
- 不做改写
- 不新增内容

### 批量仿写
- 批量 = 多次复用现有单篇链路
- 不新起并行任务系统

### 发布链路
- Markdown 优先
- `blocks` 兜底

---

## 4. 改动前先确认“主真相是否被碰到”

如果这轮需求会影响下面任一项，必须先把影响边界写清楚：

- `markdownBody`
- `wechatFinalization`
- `post-trimmer`
- `wechat-publish-mapper`
- `createRecord` / 历史记录
- 批量执行状态

如果说不清“这轮改动是否在碰主真相”，就先不要动代码。

---

## 5. 对内容工厂更稳的默认策略

### 对生成链路
- 优先改编排和约束
- 少做大而全重构

### 对发布链路
- 优先改输入来源和兼容顺序
- 少做大改版

### 对历史兼容
- 优先读取时兼容
- 不轻易一次性全量迁移

### 对内容质量
- 优先抽检核心样本
- 不先做复杂评分系统

---

## 6. 每轮需求的最小执行顺序

推荐固定按这个顺序来：

1. 用 `docs/spec-template.md` 写清楚需求
2. 判断是否碰到高成本动作
3. 如果碰到，先做 5 点复述
4. 明确主真相 / 兼容层 / 回退策略
5. 再开始代码实现
6. 按 `docs/post-change-checklist.md` 做回归

---

## 7. 不建议继续踩的坑

这些在内容工厂里已经证明很容易返工：

- 只靠 prompt 微调解决结构性问题
- 没说明主真相就直接开改
- 一边改发布，一边顺手改编辑器
- 一边改批量，一边顺手改 active record 行为
- 没有对照样本就判断“效果更好了”

---

## 8. 这份规则的用途

这份文档不是为了“流程更重”，而是为了：
- 在生成、发布、兼容这几条高成本链路上，先对齐再动手
- 减少那种“代码改完了，才发现改错了层”的返工

后续只要这份规则还贴合当前项目，就优先按它执行。
