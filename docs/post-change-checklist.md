# 内容工厂变更后必验清单

这份清单用于每次核心链路变更后的最小回归。

目标不是“大而全测试矩阵”，而是：
- 改完就能照着验
- 能快速发现主链路有没有被带坏

---

## A. 生成链路改动后必验

适用范围：
- 主写作 skill
- second-stage
- `post-trimmer`
- 生成编排

必须检查：
- 标题正常
- `markdownBody` 正常
- second-stage 正常
- `post-trimmer` 正常
- 生成结果仍能进入工作区

建议补验：
- 活人感 / 口语感是否还在
- 模板腔是否没有明显反弹

---

## B. 编辑器改动后必验

适用范围：
- `wechat-editor.tsx`
- Markdown 预览 / 导出
- 编辑器交互

必须检查：
- Markdown 编辑正常
- 微信预览正常
- 字数统计正常
- 复制 Markdown 正常
- 复制微信格式正常

建议补验：
- 左右双栏是否稳定
- 自动保存是否正常
- 刷新恢复是否正常

---

## C. 发布链路改动后必验

适用范围：
- publish mapper
- publish service
- publish snapshot

必须检查：
- 新记录发布正常
- 旧记录回退发布正常
- 发布 HTML 正常
- 发布入口不报错

建议补验：
- `markdownBody` 是否优先作为发布主来源
- `blocks` 是否仅作为兜底
- 复制微信格式与发布 HTML 是否主要一致

---

## D. 历史兼容改动后必验

适用范围：
- 历史记录读取
- `blocks -> markdownBody` 兼容
- autosave 恢复

必须检查：
- 旧记录可打开
- `blocks -> markdownBody` 兼容正常
- 自动保存正常
- 刷新恢复正常

建议补验：
- 新记录仍正常
- 不会因为兼容转换把现有记录写坏

---

## E. 批量仿写改动后必验

适用范围：
- 批量素材输入
- 批量执行状态
- 批量结果入口

必须检查：
- 批量执行状态正常
- 成功项落历史正常
- 失败项提示正常
- 不会乱切 active record

建议补验：
- 顺序执行是否仍然清楚
- 失败一篇不会打断其他篇
- 成功项能继续进入公众号编辑器

---

## F. 每轮统一收尾检查

不管改哪条链路，最后都建议统一看一遍：

- 历史记录有没有被带坏
- 自动保存有没有被带坏
- 旧记录兼容有没有被带坏
- `npm run lint` 是否通过
- `npm run build` 是否通过

---

## G. 推荐执行顺序

每次改完后，建议按这个顺序验：

1. 先验主链路
2. 再验兼容层
3. 再验页面交互
4. 最后跑 lint / build

这样更容易快速定位：
- 是主真相坏了
- 还是兼容层坏了
- 还是只是页面表现坏了

---

## H. 使用方式

这份清单不是文档摆设。

后续每次改：
- 生成
- 编辑
- 发布
- 历史兼容
- 批量仿写

都应至少挑对应的一段清单跑一遍，再算真正完成。
